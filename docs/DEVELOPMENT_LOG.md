# Development Log

## 2026-07-06 — v0.2 3D Graybox Prototype

### 方針転換の明確化

最終的な方向性は平面2Dではなく、「めっちゃカメレオン」系の**3D物理パーティアクション**。
v0.1 の 2D Canvas 版（`prototype/`）は完成版の土台ではなく、
「水流に吸い込まれる遊びが成立するか」を検証した**参考実装**として保存する。

### 目的

「3D空間で、巨大トイレの水流に吸い込まれる挙動が面白いか」の検証。

### 技術選定

- Godot 4（4.3+ 想定、Forward+）。小規模プロトタイプ向き・依存が軽い・
  グレーボックスを素早く作れる・ローカル2〜4人対戦へ拡張しやすい
- この開発環境には Godot 未インストールのため実行確認はしていない。
  人間がローカルで確認する手順を specs/v0_2_3d_graybox.md に記載

### 実装内容（`game/` ディレクトリ、`prototype/` とは独立）

- ステージ = 巨大トイレの上。便座リング（CSG円環）＋タンク（箱）＋中央の便器穴＋水面
- プレイヤー: CharacterBody3D。WASD/矢印移動、Spaceジャンプ。空中は入力が効きにくい
- 水流: idle 6s → warning 2.5s → flushing 3.5s の状態機械（flush_controller.gd、純ロジック）
- 吸引: 穴に近いほど強い加速度、空中は1.8倍。2D版で検証したバランス設計を移植
  （中央付近で無入力なら吸い込まれ、外周なら耐えられ、逃げれば抵抗できる）
- 警告演出: タンク振動・水位上昇・「ゴゴゴゴ…」点滅・カメラ微振動
- 脱落: 便器穴 → 螺旋吸い込み演出 → リスポーン。外周転落 → リスポーン
- カメラ: プレイヤー追従の見下ろし固定角。脱落演出も追うので吸い込みが画面に映る
- デバッグUI: フェーズ・残り時間・回数・イベントログ・操作説明。R でリセット
- 拡張性: 入力は `p1_*` プレフィックス、Player は `player_index` 持ち、
  吸引は問い合わせ式でプレイヤー数非依存 → v0.3 のローカル対戦に対応しやすい構造

### Codexレビュー（実施済み・静的レビュー）

- Must fix 1件: Camera3D の `current` が未設定で意図した視点にならない可能性
  → `main.tscn` に `current = true` を追加して修正済み
- Can wait として指摘（v0.3以降で対応）:
  - R キーのキーリピートで連続リセットされ得る（`is_echo()` で弾くと安定）
  - main.gd / UI / カメラが単一プレイヤー直参照（v0.3 で配列・グループ走査に切替）
  - プレイヤー同士の押し合いは CharacterBody3D だけでは発生しない（v0.3 でカスタム押し出しが必要）
  - 極端に大きい delta でフェーズ遷移が1フレーム1回のみ（実害小）
- 2D版は未変更、スコープ超過なし、不要な大規模変更なしと確認された

### 既知の問題 / 制約

- **未実行**: Godot 未インストール環境で書いたため、人間のローカル確認が必須
- 吸引・ジャンプ等の数値は2D版からの換算で暫定。実プレイ調整が必要
- 効果音・BGMなし（スコープ外）

### 次にやるべきこと

- 人間が Godot 4.3+ で開いて動作確認（specs/v0_2_3d_graybox.md のチェックリスト参照）
- 挙動が面白ければ v0.3: ローカル2〜4人対戦（押し合い・勝ち残り判定）

## 2026-07-06 — v0.1 Flush Prototype

### 目的

「巨大トイレの水流に吸い込まれるだけで面白いか」を検証する最小プロトタイプの実装。

### 技術選定

- HTML5 Canvas + 素の JavaScript（依存ゼロ、ビルド不要）
- 理由: 開発環境に Godot が未インストールで実行確認できないため。
  ブラウザで開くだけで動き、ロジックを Node.js でテストできる。
  核が面白いと確認できたら Godot 4 への移植を検討する。

### 実装内容

- `prototype/sim.js` — 物理・水流状態機械（idle 5s → warning 2.5s → flushing 3s のループ）。
  吸引はトイレへの距離で強くなる加速度。地上より空中のほうが強く流される。
  プレイヤーは配列＋スポーン地点4つで、ローカル2〜4人対戦に拡張可能な構造。
- `prototype/game.js` — Canvas 描画（巨大トイレ、渦、風パーティクル、画面振動、
  警告演出「ゴゴゴゴ…」、螺旋吸い込み演出、パニック顔）、キー入力、イベントログ。
- `prototype/index.html` — エントリポイント。
- `prototype/test_sim.js` — Node で動く簡易テスト（25件、全て成功）。
- `specs/v0_1_flush_prototype.md` — 実装スペック。
- `README.md` — 実行方法。

### バランス（テストで担保）

- 中央寄り（x=300）で無入力 → 1回の水流で流される
- 画面端で無入力 → 生き残れる（左右が安全地帯）
- 逃げ方向に入力し続ければ抵抗できる（操作不能ではない）

### Codexレビュー（実施済み）

- Must fix 1件: 脱落判定 `deathY: 500` が水面 `waterY: 524` より上で発火し、
  仕様「水面より下に到達で脱落」とずれる → `deathY: 526` に修正済み（テスト全件成功を再確認）
- Can wait として指摘（v0.2以降で対応）:
  - `game.js` が単一プレイヤー固定（`createWorld(1)`、`KEYMAPS[0]`、UIが `players[0]` 前提）
  - 吸引方向がトイレ中心ぴったりで右向きになる（中心で0が直感的）
  - 当たり判定が中心点のみ（便器のフチで半分はみ出て立てる）
  - R キーのキーリピートでリセットログが連発する
  - 極端に大きい dt でフェーズ遷移が1回分しか処理されない（描画側で dt を 1/30 に制限済みのため実害小）
- スコープ外の実装・不要な大規模変更なしと確認された

### 既知の問題

- 効果音・BGMなし（v0.1 スコープ外）
- 吸引の数値は暫定。実プレイでの調整が必要
- プレイヤーの当たり判定は中心点のみ（便器のフチで半分はみ出て立てる）
- ジャンプはキー押しっぱなしで連続ホップする（仕様未定のため放置）

### 次にやるべきこと

- 人間による実プレイ確認（面白いか・動画映えするか）
- 面白ければ v0.2: ローカル2〜4人対戦（キーマップ追加、勝敗判定、押し合い）
